**Purpose:** the tracking artifact used to cross-check implementation against the plan. If an item conflicts with the design/implementation docs, the doc wins — fix the doc first (rev bump), then the item.

**Legend:** `[ ]` not started · `[~]` in progress · `[x]` done (checked against the design) · `[!]` blocked. Every `[x]` requires the exit-check in *italics* at the end of the item to be true.

Milestone gates M0–M7 are release milestones. An item listed under a milestone is release-blocking for that milestone unless marked `(deferrable)`.

## Cross-cutting invariants — check on EVERY PR (no milestone)

These are hard-won correctness rules — each one closes a real class of bug seen in production job-queue systems — turned into standing review rules:

| # | Rule | Category |
|---|---|---|
| X1 | Claim readiness (`run_at <= now()`) is revalidated inside the locking SQL statement — never split find/lock into two statements (prevents claiming not-yet-ready jobs under concurrent claimers) | Claim path |
| X2 | DB `now()` is the only clock in SQL; no client timestamps in queries | Claim path |
| X3 | Dispatcher/sweeper/cron pass exceptions are contained + counted, never loop-fatal | Loop safety |
| X4 | Worker slot release happens in done-callbacks only; task set strong-referenced; drain bookkeeping independent of accepting-flag (prevents slot leaks/double-release) | Worker runtime |
| X5 | Every sweeper statement carries full tenant/state/lease scope (prevents cross-tenant or healthy-lease interference) | Sweeper |
| X6 | Cancel handles every job state explicitly (matrix above) | Cancel |
| X7 | Job identity (id) is stable across retries — retry mutates the row, never re-enqueues | Retry |
| X8 | Status/read APIs are single-snapshot (one query/transaction), never composed reads (prevents torn reads across concurrent writers) | Read APIs |
| X9 | Middleware exceptions are suppressed, never job- or loop-fatal | Worker runtime |
| X10 | No per-job advisory locks, ever; advisory locks only for election (sweeper/migrations) and opt-in `strict_group_caps` | Concurrency |
| X11 | New periodic/computed intervals are clamped ≥ 0 at the boundary | Loop safety |
| X12 | No NOTIFY anywhere; polling + optional in-process wake events only (avoids known NOTIFY-channel outage classes) | Architecture |
| X13 | `job_events` writes stay behind the single ledger-writer path (never scattered) — keeps TODOS.md #1 (write buffering) possible | Observability |
| X14 | SymbaTest conformance: any engine semantic change lands with its SymbaTest twin in the same PR | Testing |
| X15 | Doc supremacy: behavior differing from the design docs requires a doc rev bump in the same PR | Process |
